# MMC タイム集計

自転車レース Magic Mushroom Cup(MMC)のタイム集計をブラウザ上で行うツールです。
2本走ってタイムを競う形式の大会を想定しています。計測そのものは外部の計測ソフトで行い、
このツールはその前後の事務作業(エントリー整理、スタートリスト作成、結果の集計、リザルト表の印刷)を担当します。

もとは Excel のマクロ付きブックで運用していたものを、ブラウザだけで動くように移植したものです。

OldTimer クラスは MMC44 から追加しました。

## 使い方

ブラウザで開くだけです。インストールも設定も要りません。

- **オンライン**: https://projectsubmarine.github.io/mmc-timing/
- **オフライン**: `index.html` をダウンロードしてダブルクリック

外部ライブラリを使っていない HTML 1枚なので、ネットワークが無い会場でも動きます。
（後述の「リザルトの共有」を設定したときだけ、公開ボタンを押した瞬間に通信します）

## 処理の流れ

画面上部の9ステップを順に進めます。

| | 画面 | やること |
|---|---|---|
| 1 | 名簿取込 | 申込名簿のテキストを貼り付けて、名前とフリガナに分ける |
| 2 | エントリー | クラスごとにビブ番号と名前を入力する |
| 3 | スタートリスト1本目 | 出走順を作り、計測ソフトに渡す CSV を書き出す |
| 4 | 1本目リザルト | 計測ソフトが出した CSV を読み込み、必要なら手で直す（手入力もできる） |
| 5 | 1本目クラス別 | クラスごとのタイム順と、2本目の出走順を確認する |
| 6 | スタートリスト2本目 | 2本目の出走順を作り、CSV を書き出す |
| 7 | 2本目リザルト | 2本目の CSV を読み込む |
| 8 | 最終リザルト | 1本目と2本目を突き合わせて順位を出し、印刷する |
| 9 | Web用 | 掲載用に全クラスの結果をまとめて書き出す |

手入力でよければ 1 は飛ばして 2 から始めて構いません。

### タイムの手入力

Kids のように計測ソフトを通さず手集計するクラスや、CSV に入らなかった選手は、
リザルト画面(手順4・7)の **「エントリーから追加」** を使います。クラスを選んで押すと、
**まだリザルトに行が無い出走者**がビブ・名前の入った行として表に並びます。
あとは Time にタイムを打ち、Enter を押すと下の行に移ります。

- 対象は出走予定の人だけです。2本目の Expert は、1本目を走った人(決勝進出者)だけが出ます。
- 何度押しても同じ人は増えません。すでに行がある人は対象外になります。
- ビブが空欄のエントリーは出ません。先にエントリー画面でビブを入れてください。

## 名簿の取り込み

申込名簿が次のような形になっていれば、そのまま貼り付けて取り込めます。

```
○エキスパート
山田太郎　ヤマダタロウ　６０００円
佐藤　花　サトウハナ（○○サイクル）

○スポーツ
井ノ口学　イノクチ　マナブ　６０００円
```

- `○クラス名` でクラスを区切ります。クラス名を判定できなかった見出しは、取り込み先を選ぶか、取り込まないままにできます。
- 金額と所属（かっこ書き）は取り除きます。
- 名前の中の空白は詰めます（`佐藤　花` → `佐藤花`）。
- フリガナは行の右側から拾うので、`井ノ口学` のように名前にカタカナが混じっていても正しく分かれます。
- 取り込んだ時点ではビブは空欄です。エントリー画面で入力してください。

## 集計の決まりごと

- クラスは7つあり、**ビブ番号の百の位**でクラスが決まります。
  1=Expert、2=Sports、3=Beginner、4=Girls、5=Junior、6=Kids、**9=OldTimer**
  （OldTimer だけ 7 ではなく 9 です。7xx と 8xx はどのクラスにもなりません）
- 出走順は Kids → Junior → Girls → Beginner → Sports → Expert → OldTimer の順です。
- OldTimer は他クラスと同じく2本走り、速い方（ベストタイム）で順位が決まります。
- **Expert だけ方式が違います。** 1本目が予選、2本目が決勝で、決勝の出走順は予選タイムの遅い順、
  順位は決勝タイムで決まります。他のクラスは2本のうち速い方(ベストタイム)で順位が決まります。
- タイムは `mm:ss.fff`(例 `00:23.031`)の文字列として扱います。Kids は計測方法が違うため
  小数2桁(例 `00:16.29`)ですが、分と秒が2桁ゼロ埋めであれば比較は正しく働きます。
- 1本目と2本目の突き合わせは**ビブ番号**で行います。同じビブが複数行あるときは下の行を採用します。
- 同じタイムの選手は同順位になります。タイムが無い選手は順位が付きません。

## 計測ソフトとやり取りする CSV

いずれも**見出し行なし、Shift-JIS**です。

- **書き出す**(このツール → 計測ソフト): `ビブ,名前` の2項目
- **読み込む**(計測ソフト → このツール): 9項目のうち、2番目(ビブ)、3番目(名前)、5番目(タイム)を使います

再計測などで同じビブが複数行出ることがあるため、読み込んだ後に画面上の表で手直しできるようにしてあります。

## データの保存

入力した内容はブラウザの localStorage に自動保存されます。別の端末に移したり
バックアップを取りたいときは「データを保存」で JSON ファイルに書き出してください。

**初期状態では、入力したデータが外部に送られることはありません。** 通信は一切行わず、
すべてブラウザの中だけで処理します。後述の「リザルトの共有」を設定した場合にかぎり、
「公開」を押したときだけ、スタートリストとリザルトが送られます。

## リザルトの共有（任意・初期状態では無効）

集計するのは1人で、他のスタッフはスタートリストとリザルトを見るだけ、という場合に使えます。
編集した人が **「公開」** を押すと、そのときの内容が送られ、**閲覧用 URL** を開いた人の画面に反映されます。

- 閲覧用 URL は `…/mmc-timing/#view/<大会ID>` です。「閲覧用 URL」ボタンでコピーできます。
- 閲覧側はスタートリスト1本目・1本目クラス別・スタートリスト2本目・最終リザルトの4画面だけを見られます。
  編集も書き出しもできません。
- **自動では送りません。** 押したときだけです。リザルトは取り込んだ直後に手で直す前提なので、
  直しかけの順位が見えないようにしてあります。クラスが終わるたびに押す使い方を想定しています。
- 送るのはビブ・名前・タイムだけです。**フリガナは送りません。**
- 閲覧側は、最後に受け取った内容を端末に残します。電波が切れても直前の表は見られます
  （そのときは上部に「通信なし」と出ます）。

### 設定

初期状態では無効で、何も通信しません。使うには Firebase のプロジェクトを作り、
`index.html` の先頭近くにある `FIREBASE` に設定値を入れます。

```js
const FIREBASE = {
  config: { apiKey: '…', authDomain: '…', projectId: '…', appId: '…' },
  eventId: 'mmc44',    // 大会ごとに変えると前の大会の分が残る
};
```

Firebase 側では次の2つを設定します。

- **Firestore のルール** — 読みは全員、書きは自分だけ。

  ```
  match /databases/{db}/documents/events/{id} {
    allow read: if true;
    allow write: if request.auth != null && request.auth.token.email == '<自分のアドレス>';
  }
  ```

- **Authentication** — Google ログインを有効にし、承認済みドメインに公開先のドメインを入れる。

公開した内容は URL を知っていれば誰でも読めます。会場に貼り出し、Web にも掲載するもの
（ビブ・名前・タイム）だけを送るようにしてあるのはこのためです。

## 印刷

スタートリストは55行×3列で1ページに収まるレイアウトになります。
クラスの変わり目にはクラス名の区切りが1行入ります(その列の最後の行に来てしまう場合は、
見出しだけが取り残されないよう、そのクラスごと次の列の先頭から始めます)。
リザルト表はクラスごとに印刷します。ブラウザの印刷機能をそのまま使ってください。
